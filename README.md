# NovelForge · AI 小说创作台

本地运行的 AI 长篇创作工作台。一条命令启动，浏览器里写小说；AI 负责续写、改写、润色，你负责故事。

## 快速开始

### Windows 一键启动（推荐）

双击 **`启动.bat`**，约 12 秒后浏览器会自动打开。写作时保持那个黑色窗口开着，关掉它即停止服务。

### 命令行启动

```bash
pnpm install      # 安装依赖
pnpm seed         # （可选）生成一部演示作品，先看看效果
pnpm dev          # 启动开发环境
```

打开 http://127.0.0.1:5173 ，会先看到**书架**（所有作品一览）。点某一本书进入写作台，左上角「← 书架」随时返回。

首次使用点 **⚙ 设置**，填入模型配置。

### 接入模型（OpenAI 兼容）

**最省事：直接复用 DeepSeek Harness 的登录**

如果你本机装过 DeepSeek Harness 并登录了 DeepSeek，打开 **⚙ 设置** 顶部会看到「从 DeepSeek Harness 导入」，
点一下就会把它的 DeepSeek Key 复制成一套配置并设为当前，不用手抄 Key。

- 只读：不会修改 DSH 的任何文件
- Key 存进 NovelForge 自己的数据库，不会上传

**手动配置**：点 **⚙ 设置 → ＋ 添加**，可以直接点常用服务商预设（DeepSeek / OpenAI / 通义 / 本地 Ollama）一键填好地址和模型：

| 服务 | Base URL | 模型名示例 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-max` |
| 本地 Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:14b` |

**可以存多套配置**，比如「DeepSeek 日常用」和「Ollama 离线用」各存一套，点「设为当前」随时切换，不用来回改 Key。

填好 Base URL 和 Key 后点 **「拉取模型」**，会自动请求服务商的 `/models` 接口，模型名变成下拉列表供选择；服务商不支持时也可以手填。

换成任何实现了 `/chat/completions` 的服务都能直接用，**不需要改代码**。

### 生产模式（单进程，前后端合一）

```bash
pnpm build
NODE_ENV=production pnpm start
# 访问 http://127.0.0.1:8787
```

### 想在手机/平板上写（局域网访问）

默认只监听 `127.0.0.1`，别的设备连不上。要让同一 Wi-Fi 下的设备访问，必须同时给一个访问令牌：

```bash
ACCESS_TOKEN=自己起一个长口令 HOST=0.0.0.0 pnpm start
# 然后访问 http://<电脑的局域网IP>:8787
```

第一次打开会提示输入令牌，输一次就记住了。

> 不设 `ACCESS_TOKEN` 而直接用 `HOST=0.0.0.0` 启动时，服务会**拒绝启动**并给出提示。
> 因为没有任何账号体系，一旦裸暴露到局域网，同网段的人可以读写你全部作品、用你的 Key 生成内容。
> 确实要走公网，请在前面加一层反向代理并启用 HTTPS。

## 功能

- **书架（主页）** —— 打开软件先看到所有作品：卡片式列表、搜索、新建 / 编辑 / 删除，显示章数、字数、设定数与完成度；点书进入写作台
- **AI 生成小说** —— 书架上描述你想写的故事，AI 直接产出书名、简介、文风、人物设定和卷章大纲；预览确认后一键建书
- **设定库** —— 世界观 / 人物 / 势力 / 名词 / 物品 / 地点；支持别名、结构化字段、正文；可"固定注入"到每次生成
- **设定中心（一致性引擎）** —— 硬约束（考据/制度/称谓规则，优先级最高且每次都注入）、脑暴板、伏笔台账、时间线、知识库、AI 一致性检查（人物突变 / 时间线矛盾 / 设定吃书 / 称呼不一致 / **史实制度常识错误** / 伏笔有埋无收）
- **AI 生成目录** —— 两段式：先只出章节名（千章也只要几分钟），大纲后期用「补全缺失大纲」按批补；也可一次性连大纲生成
- **按卷扩展** —— 一卷一卷地扩：指定卷与章数（默认 50），生成后立即写入该卷；扩到上千章就用它
- **分层创作** —— 大纲 → 细纲（节拍）→ 场景卡（目标·阻力·结果）→ 成稿；细纲和场景会进入写作上下文
- **知识库** —— 上传设定集 / 参考文档 / 风格样本（.txt/.md），写作时按本章大纲自动检索并注入，提示词里标明「作者资料」来源
- **卷章结构** —— 卷下分章，章节带大纲与状态；支持重命名、删除
- **AI 写作** —— 续写 / 改写 / 润色 / 扩写 / 仿写，SSE 流式输出，可随时停止
- **长期记忆** —— 自动把「固定设定 + 卷摘要 + 前几章摘要 + 本章大纲」拼进上下文，长篇不崩
- **导出** —— TXT / Markdown / Word（DOCX 带标题层级）
- **AI 配图** —— 封面与插图（需单独的图像模型）

首次启动会自动带入一部演示作品《长夜行》。运行 `pnpm seed` 可补齐演示数据（只补缺失项，不会覆盖你写的内容）。

## 用 AI 从零生成一部小说

书架上点 **✨ AI 生成小说**，会先和你聊几句：

1. 你说一句想写的方向（也可以直接点「古典玄幻 / 都市悬疑 / 科幻末世」这些快捷选项）
2. AI 会反问类型、主角、基调这些还没定的部分，一次只问一个，并给可点选的选项
3. 聊清楚了 AI 会汇总出一份需求，点 **开始生成方案**
4. AI 产出完整方案：

- 书名、一句话简介、题材
- 文风要求（会作为之后每次生成的基准）
- 叙述视角（按题材给建议，预览里可以改）
- 人物 / 势力 / 世界观等设定条目（主角会自动设为「固定注入」）
- 分卷的章节大纲

预览不满意点「← 回到对话」继续调整；点「创建这本书」才会真正落库，并直接进入写作台。

不想聊天也行，底部「直接生成」会用你已说的内容直接出方案。

**规划章数可以自己填**（1–1000 章），下面的数字只是快捷预设。卷数按每卷约 40 章自动分配
（100 章约 3 卷，1000 章约 20 卷）。
如果 AI 给的章数和你要求的不一致，预览里会明确提示「你要求 N 章，AI 给了 M 章」，你可以重生成或直接接受。

> **章节多时会自动分批**：超过 10 章就先出骨架、再每批 20 章写大纲。
> 几百章大概要几分钟，1000 章可能十几分钟，期间别关窗口。
> 遇到服务商限流会自动重试，不用手动重来。

生成的是**骨架**，正文还需要你在写作台里逐章用 AI 续写或自己写。

### 章节可以单独重做

- **方案预览里**：每章右侧悬停出现 `↻ 重做`，只重做这一章的标题和大纲，其它章节不动
- **写作台里**：右侧 AI 面板有 `整章生成`（按大纲写完整一章）和 `整章重写`（参考现有正文重写），
  生成完点 `替换正文` 整段替换；已经写好的章节也能推倒重来

### 数据安全

服务器每 6 小时自动把数据库备份到 `apps/server/data/backups/`（保留最近 10 份）。
删除作品或章节前，还会把内容完整存一份 JSON 留档，误删可以从这里找回。

## 架构

```
novelforge/
├── packages/shared/          # 唯一的前后端契约：领域模型 + 类型
├── apps/server/              # Fastify + node:sqlite
│   └── src/
│       ├── ai/               # 模型客户端 + 上下文拼装（核心）
│       ├── repos/            # 数据访问，每个实体一个文件
│       ├── routes/           # 路由，按资源拆分
│       ├── db.ts             # 建表与迁移
│       └── config.ts         # 路径与端口
└── apps/web/                 # React + Vite + zustand
    └── src/
        ├── api/              # HTTP 与 SSE 客户端
        ├── store/            # 全局状态
        └── components/       # 视图组件
```

### 为什么这样分层

- **契约先行**：所有类型都在 `packages/shared`，前后端只从这里导入。改接口 = 改一个文件，TypeScript 会报出所有需要同步的地方。
- **AI 逻辑集中**：`ai/context.ts` 是「记忆注入」的唯一实现。想让 AI 更懂你的设定，只改这一个文件。
- **零原生依赖存储**：用 Node 24 内置的 `node:sqlite`，不用编译 better-sqlite3，换机器不折腾。
- **路由与仓储分离**：路由只管校验与响应，`repos/` 只管 SQL。

## 检查更新

设置页底部有「版本与更新」：显示当前版本、提交号与分支，点「检查更新」会对比 GitHub 上的 `main`。

- 只读访问 GitHub 公共接口，**不上传任何作品内容或 Key**
- 有新版本时直接给出升级命令，并提醒先备份 `apps/server/data`
- 压缩包安装（没有 `.git`）无法比对，会提示重新下载覆盖
- 检测结果缓存 10 分钟，避免耗尽 GitHub 未认证接口的额度

## 叙述视角

设的是**默认视角**，不是全书唯一视角——长篇不可能一种视角写到底。

| 默认视角 | 场景内的规则 |
| --- | --- |
| 第一人称限知 | 一律用「我」；不写他人心理；不写「我」不在场的场景 |
| 第三人称限知 | 场景内只跟一个视角人物；同场景不跳内心 |
| 第三人称全知 | 可进任何角色内心；但不得提前泄底；不与限知横跳 |
| 多视角轮换 | 每个场景一个视角；靠分节标记让人认出来 |
| 未指定 | 不注入，由文风与正文推断（老作品保持原样） |

**允许的视角切换**（一行一条）用来声明例外，比如：

```
每卷最后一章切到反派视角，另起一节并以人名开头
亲密场景结束后可切到另一方，用空行分节
插入书信、审讯记录时可直接换载体
```

不填就默认只在换章、分节、时空跳转时允许切换。

### 章节级覆盖

楔子、序章、尾声这类章节可以单独设视角：写作台里「本章视角」下拉，留空即继承项目默认。

新建章节时，标题以「楔子 / 序章 / 序幕 / 引子 / 序言 / 前言」开头的会自动设为**第三人称全知**
——这类章节通常是上帝视角交代前史。改名或手动切换都能改掉。

一致性检查会把这些章节单独列出来，按各自的视角判断，不会按项目默认误报。

一致性检查按这套规则判断：**符合规则且有标记的切换不报**；只报场景内跳进别人内心（high）、
写视角人物感知不到的信息（high）、未声明或缺标记的切换（medium）。

## 写前查资料与写作约束

两个专门对付「写错内容」的功能，都在写作台里。

### 写前查资料

大纲写好后，点「写前查资料 → AI 列事实清单」：

1. AI 先判断这本是历史向还是架空，再列出这一章「写错就成硬伤」的事实点（3-8 条，必查的会标出来）
2. 拿每条事实点的关键词去你的资料库检索，命中的片段直接显示在下面
3. 清单会存进本章，之后写正文时用这些关键词去检索资料，而不是只用标题和大纲

为什么有用：正文生成时的检索原本只拿「章节标题 + 大纲前 200 字」做关键词匹配，
大纲里没写到的词召回不来。先让 AI 把要核实的点展开，召回面大很多。

### 写作约束

一致性检查里 **high 级**的问题会自动沉淀成「写作约束」，下次生成正文时注入上下文，
避免同一处错两遍。

- 写作台顶部显示「N 条写作约束生效中」，点「查看」看具体条目
- 改好后点「已解决」，之后生成不再带这条
- 相同文字不会重复堆积：同一条问题检查十次也只算一条

## 数据在哪

全部在 `apps/server/data/`：

- `novelforge.db` —— 作品、设定、章节（SQLite）
- `images/` —— 生成的图片
- `exports/` —— 导出缓存

**API Key 也存在这个库里，不会上传到任何地方。**

⚠️ 注意：Key 在数据库中是**明文**（本地单人工具的取舍）。`data/backups/` 里的自动备份同样含明文 Key，
所以不要把 `data/` 目录或备份文件发给别人、也不要把整个项目目录传到公开仓库。

备份整个 `data/` 目录即可。

可用 `NOVELFORGE_DATA_DIR` 环境变量把数据放到别处。

## 上下文是怎么拼的

每次生成时，`buildContext()` 按优先级往提示词里塞内容，默认预算 20000 字符（约 1.3 万 token）：

**必选项**：一定注入，也计入预算；每块有上限，超出会截断并在「记忆使用」里标明

1. 作者硬约束（上限 6000 字）
2. 本章大纲（4000）→ 本章细纲（3000）→ 场景卡（2000）
3. 文风要求（1000）

**可裁剪项**：预算不够就跳过后面的条目，不会因为一条放不下就丢掉整段

4. 固定注入的设定条目
5. 未回收伏笔、关键时间点
6. 本卷概要
7. 前几章摘要（越近越优先，最多 30 章；单条放不下会跳过，继续试更早的）
8. 作者资料检索命中（最多 3 条）

必选项的上限之和是 16000，小于默认预算，所以即使作者把硬约束和大纲都写满，
也天然给记忆留了 4000 字——长篇写到几百章时，前情摘要不会因为设定太长被整段挤掉。
右侧「记忆使用」会列出每一项实际占了多少字，写满了可以据此精简。

（本章正文结尾 2500 字或你选中的片段，是作为用户消息附上的，不占这块预算。）

想调整策略，改 `apps/server/src/ai/context.ts`。

## 扩展指引

- **加一个新的设定类型**：改 `shared` 里的 `EntityType`，在 `EntityManager.tsx` 的 `TYPE_LABEL` 加一项，其余自动生效。
- **加一种写作模式**：改 `shared` 的 `WriteMode`，在 `context.ts` 的 `MODE_INSTRUCTION` 加指令，在 `AiPanel.tsx` 的 `MODES` 加标签。
- **加一种导出格式**：改 `shared` 的 `ExportFormat`，在 `export.routes.ts` 加一个分支。
- **换数据库**：只需替换 `repos/` 下的实现，路由层不用动。
