# NovelForge · AI 小说创作台

本地运行的 AI 长篇创作工作台。一条命令启动，浏览器里写小说；AI 负责续写、改写、润色，你负责故事。

## 快速开始

### Windows 一键启动（推荐）

双击 **`启动.bat`**，约 12 秒后浏览器会自动打开。写作时保持那个黑色窗口开着，关掉它即停止服务。

### 命令行启动

```bash
pnpm install      # 安装依赖
pnpm seed         # （可选）生成一部演示作品，先看看效果
pnpm dev          # 启动开发环境
```

打开 http://127.0.0.1:5173 ，会先看到**书架**（所有作品一览）。点某一本书进入写作台，左上角「← 书架」随时返回。

首次使用点 **⚙ 设置**，填入模型配置。

### 接入模型（OpenAI 兼容）

点 **⚙ 设置 → ＋ 添加**，可以直接点常用服务商预设（DeepSeek / OpenAI / 通义 / 本地 Ollama）一键填好地址和模型：

| 服务 | Base URL | 模型名示例 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-max` |
| 本地 Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:14b` |

**可以存多套配置**，比如「DeepSeek 日常用」和「Ollama 离线用」各存一套，点「设为当前」随时切换，不用来回改 Key。

填好 Base URL 和 Key 后点 **「拉取模型」**，会自动请求服务商的 `/models` 接口，模型名变成下拉列表供选择；服务商不支持时也可以手填。

换成任何实现了 `/chat/completions` 的服务都能直接用，**不需要改代码**。

### 生产模式（单进程，前后端合一）

```bash
pnpm build
NODE_ENV=production pnpm start
# 访问 http://127.0.0.1:8787
```

## 功能

- **书架（主页）** —— 打开软件先看到所有作品：卡片式列表、搜索、新建 / 编辑 / 删除，显示章数、字数、设定数与完成度；点书进入写作台
- **AI 生成小说** —— 书架上描述你想写的故事，AI 直接产出书名、简介、文风、人物设定和卷章大纲；预览确认后一键建书
- **设定库** —— 世界观 / 人物 / 势力 / 名词 / 物品 / 地点；支持别名、结构化字段、正文；可"固定注入"到每次生成
- **设定中心（一致性引擎）** —— 伏笔台账（埋在哪章、计划何时回收）、时间线、AI 一致性检查（人物突变 / 时间线矛盾 / 设定吃书 / 称呼不一致 / 伏笔有埋无收）；未回收伏笔会自动注入生成上下文
- **卷章结构** —— 卷下分章，章节带大纲与状态；支持重命名、删除
- **AI 写作** —— 续写 / 改写 / 润色 / 扩写 / 仿写，SSE 流式输出，可随时停止
- **长期记忆** —— 自动把「固定设定 + 卷摘要 + 前几章摘要 + 本章大纲」拼进上下文，长篇不崩
- **导出** —— TXT / Markdown / Word（DOCX 带标题层级）
- **AI 配图** —— 封面与插图（需单独的图像模型）

首次启动会自动带入一部演示作品《长夜行》。运行 `pnpm seed` 可补齐演示数据（只补缺失项，不会覆盖你写的内容）。

## 用 AI 从零生成一部小说

书架上点 **✨ AI 生成小说**，会先和你聊几句：

1. 你说一句想写的方向（也可以直接点「古典玄幻 / 都市悬疑 / 科幻末世」这些快捷选项）
2. AI 会反问类型、主角、基调这些还没定的部分，一次只问一个，并给可点选的选项
3. 聊清楚了 AI 会汇总出一份需求，点 **开始生成方案**
4. AI 产出完整方案：

- 书名、一句话简介、题材
- 文风要求（会作为之后每次生成的基准）
- 人物 / 势力 / 世界观等设定条目（主角会自动设为「固定注入」）
- 分卷的章节大纲

预览不满意点「← 回到对话」继续调整；点「创建这本书」才会真正落库，并直接进入写作台。

不想聊天也行，底部「直接生成」会用你已说的内容直接出方案。

**规划章数可以自己填**（1–1000 章），下面的数字只是快捷预设。卷数按每卷约 40 章自动分配
（100 章约 3 卷，1000 章约 20 卷）。
如果 AI 给的章数和你要求的不一致，预览里会明确提示「你要求 N 章，AI 给了 M 章」，你可以重生成或直接接受。

> **章节多时会自动分批**：超过 10 章就先出骨架、再每批 20 章写大纲。
> 几百章大概要几分钟，1000 章可能十几分钟，期间别关窗口。
> 遇到服务商限流会自动重试，不用手动重来。

生成的是**骨架**，正文还需要你在写作台里逐章用 AI 续写或自己写。

### 章节可以单独重做

- **方案预览里**：每章右侧悬停出现 `↻ 重做`，只重做这一章的标题和大纲，其它章节不动
- **写作台里**：右侧 AI 面板有 `整章生成`（按大纲写完整一章）和 `整章重写`（参考现有正文重写），
  生成完点 `替换正文` 整段替换；已经写好的章节也能推倒重来

### 数据安全

服务器每 6 小时自动把数据库备份到 `apps/server/data/backups/`（保留最近 10 份）。
删除作品或章节前，还会把内容完整存一份 JSON 留档，误删可以从这里找回。

## 架构

```
novelforge/
├── packages/shared/          # 唯一的前后端契约：领域模型 + 类型
├── apps/server/              # Fastify + node:sqlite
│   └── src/
│       ├── ai/               # 模型客户端 + 上下文拼装（核心）
│       ├── repos/            # 数据访问，每个实体一个文件
│       ├── routes/           # 路由，按资源拆分
│       ├── db.ts             # 建表与迁移
│       └── config.ts         # 路径与端口
└── apps/web/                 # React + Vite + zustand
    └── src/
        ├── api/              # HTTP 与 SSE 客户端
        ├── store/            # 全局状态
        └── components/       # 视图组件
```

### 为什么这样分层

- **契约先行**：所有类型都在 `packages/shared`，前后端只从这里导入。改接口 = 改一个文件，TypeScript 会报出所有需要同步的地方。
- **AI 逻辑集中**：`ai/context.ts` 是「记忆注入」的唯一实现。想让 AI 更懂你的设定，只改这一个文件。
- **零原生依赖存储**：用 Node 24 内置的 `node:sqlite`，不用编译 better-sqlite3，换机器不折腾。
- **路由与仓储分离**：路由只管校验与响应，`repos/` 只管 SQL。

## 数据在哪

全部在 `apps/server/data/`：

- `novelforge.db` —— 作品、设定、章节（SQLite）
- `images/` —— 生成的图片
- `exports/` —— 导出缓存

**API Key 也存在这个库里，不会上传到任何地方。** 备份整个 `data/` 目录即可。

可用 `NOVELFORGE_DATA_DIR` 环境变量把数据放到别处。

## 上下文是怎么拼的

每次生成时，`buildContext()` 按优先级往提示词里塞内容，直到用完 token 预算（默认 6000 字符）：

1. 固定注入的设定条目（人物、世界观……）
2. 本卷摘要
3. 前几章摘要（越近越优先，最多 30 章）
4. 本章大纲（强制遵守）
5. 文风要求
6. 本章正文结尾 2500 字 / 或你选中的片段

想调整策略，改 `apps/server/src/ai/context.ts`。

## 扩展指引

- **加一个新的设定类型**：改 `shared` 里的 `EntityType`，在 `EntityManager.tsx` 的 `TYPE_LABEL` 加一项，其余自动生效。
- **加一种写作模式**：改 `shared` 的 `WriteMode`，在 `context.ts` 的 `MODE_INSTRUCTION` 加指令，在 `AiPanel.tsx` 的 `MODES` 加标签。
- **加一种导出格式**：改 `shared` 的 `ExportFormat`，在 `export.routes.ts` 加一个分支。
- **换数据库**：只需替换 `repos/` 下的实现，路由层不用动。
